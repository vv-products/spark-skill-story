# Data migration script for content + missions

Goal: a single SQL file of INSERT statements that fills a freshly-set-up clone (tables already created via `docs/DB-SETUP.sql`) with the current content and mission data. Structure only exists there today; this adds the rows.

## New file: `docs/DB-DATA.sql`

Rows exported from the live database, in dependency order so foreign keys always resolve:

1. **Content library**
   - pillars (4)
   - topics (20)
   - modules (100)
   - classes (40)
   - layers (173) — includes each layer's full `config` JSON, so every task inside a class comes across intact
2. **Crossword missions**
   - mission_crosswords (1)
   - mission_crossword_variants (3 — easy/medium/hard)
   - mission_crossword_words (13)
3. **Quiz missions**
   - mission_quizzes (2 — self-paced and quick-fire)
   - mission_quiz_questions (20)
   - mission_quiz_choices (80)
4. **Presentation content** (included because the app reads it on first load)
   - avatars (8)
   - welcome_cards (4)

## How it behaves

- Original `id` values are preserved, so all parent/child links stay valid and the script can be re-run safely.
- Every insert ends with `on conflict (id) do nothing`, so running it twice does not duplicate or overwrite anything.
- Wrapped in a single transaction — if anything fails, nothing is half-applied.
- No user data: no profiles, roles, XP events, progress, friendships, or friend codes. The clone's first sign-up still becomes admin/editor as usual.
- Image URLs inside `avatars`, `welcome_cards`, and class hero fields still point at the current project's storage. Note in the file header: they keep working as public URLs, but to be fully independent the files must be copied into the clone's buckets and the URLs updated.

## How to use it

Paste the file contents into the clone project's chat and ask it to run the data inserts (or run it against the target database directly) after `docs/DB-SETUP.sql` has been applied.

## Technical notes

- Values are generated by reading the live rows and emitting literal, properly escaped INSERTs (JSON/array columns cast explicitly to `jsonb` / `text[]`).
- Column lists are written out explicitly rather than relying on table order, so the script survives later column additions.
- A copy is also placed in the downloadable documents folder.
